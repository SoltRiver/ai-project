# データ基盤アーキテクチャ：二層構成の運用ルール

## 概要

本プロジェクトは **二層構成** でデータを管理する。

```
Codex CLI
├─ EDINET DB（最新取得・外部参照）
└─ 自作DB（過去分析・独自加工データ）
```

- **EDINET DB** = 最新の財務・開示データを外部参照する層
- **自作DB** = 過去分析・独自指標・キャッシュ・統合結果を保持する層

両者の責務は明確に分離する。


## データ責務の定義

### EDINET DB（外部参照層）

| 項目 | 内容 |
|---|---|
| **位置づけ** | 外部サービス（edinetdb.jp） |
| **接続方式** | Codex CLI → MCP プロトコル |
| **重視する性質** | 最新性 |
| **主な用途** | 最新データ取得、都度参照、スクリーニング、比較分析 |
| **データ寿命** | 取得のたびに最新化される（過去は保証しない） |
| **運用主体** | 外部サービス運営者 |

### 自作DB（内部分析層）

| 項目 | 内容 |
|---|---|
| **位置づけ** | ローカルDB（SQLite / PostgreSQL） |
| **接続方式** | SQLAlchemy ORM / 既存バッチ / FastAPI |
| **重視する性質** | 再現性・安定性 |
| **主な用途** | 履歴蓄積、独自加工指標、高速表示、キャッシュ、AI分析結果 |
| **データ寿命** | 明示的に削除するまで保持 |
| **運用主体** | 開発チーム（自分） |

## 使い分けルール

### ○ 正しい使い方

| シナリオ | 使う層 |
|---|---|
| 直近の財務値や開示情報を確認 | EDINET DB |
| 最新のスクリーニング | EDINET DB |
| 異なる企業の最新データを比較 | EDINET DB |
| 過去数年分の推移を確認 | 自作DB |
| 独自スコア・加工済み指標を参照 | 自作DB |
| アプリ画面に高速表示 | 自作DB |
| グラフ・チャートの描画 | 自作DB |
| AI分析結果の保持 | 自作DB |

### ✗ やってはいけないこと

| 禁止事項 | 理由 |
|---|---|
| EDINET DB を自作DBの代替として扱う | 責務が異なる |
| EDINET DB を自作DBの内部テーブルとして扱う | 外部サービスである |
| 「EDINET DB」と「EDINET API取得結果を保存した自作DB」を同一視する | 保存済みデータは自作DBの管轄 |
| EDINET DB のレスポンスを無検証で自作DBに即時反映 | データ品質を担保できない |
| 自作DBの接続設定・ORM・マイグレーションを EDINET DB のために変更する | 既存システムを壊す |

## 保存ポリシー

### 原則

1. **すべてを自動保存しない** ― EDINET DB から取得した結果を自動で自作DBに書き込まない
2. **保存対象は明示的に選ぶ** ― 何を・なぜ保存するかをバッチ処理で定義する
3. **メタデータを持たせる** ― 保存時には以下を必ず記録する
   - 取得日時
   - 取得元（EDINET DB / EDINET API / yfinance 等）
   - 対象企業（銘柄コード）
   - 対象期間
4. **混在表示しない** ― 「EDINET DB由来の最新値」と「自作DB内の確定分析値」を同一画面で区別なく表示しない

### EDINET DB → 自作DB への反映フロー（将来設計）

```
EDINET DB (MCP)
    │
    ├── 1. Codex CLI で最新データ参照
    │
    ├── 2. 分析・検証
    │
    ├── 3. 保存判断
    │     ├── 保存しない → 参照で完了
    │     └── 保存する  → バッチ処理へ
    │
    └── 4. バッチ処理
          ├── 取得元・日時を付与
          ├── 型変換・正規化
          └── 自作DBの適切なテーブルに INSERT/UPSERT
```

## 設定ファイルの管理

### Codex CLI （EDINET DB MCP 接続）

| ファイル | 場所 | 用途 |
|---|---|---|
| `config.toml` | `%USERPROFILE%\.codex\config.toml` | MCP サーバー定義（edinetdb_mcp） |
| `set-edinetdb-mcp-key.ps1` | `scripts/` | APIキー登録スクリプト |
| `set-edinetdb-mcp-key.bat` | `scripts/` | .bat ラッパー |

### 自作DB （既存アプリ）

| ファイル | 場所 | 用途 |
|---|---|---|
| `.env` | プロジェクトルート | EDINET API KEY, OPENAI KEY 等 |
| `database.py` | プロジェクトルート | SQLAlchemy 接続設定 |
| `models/` | プロジェクトルート | ORM モデル定義 |

> **重要**: EDINET DB MCP の設定作業は上記の自作DB設定ファイルに一切触れない。

## 命名規則

混同を防ぐため、以下の命名を徹底する。

| 対象 | 命名 | NG例 |
|---|---|---|
| 外部MCP接続 | `edinetdb_mcp` | `local_db`, `edinet_db`, `db` |
| 環境変数 | `EDINETDB_AUTH` | `API_KEY`, `EDINET_KEY` |
| 自作DB | `自作DB`, `内部分析DB`, `ai_project.db` | `EDINET DB`, `edinet_db` |
| EDINET API取得結果（自作DB内） | `EDINET API取得済みデータ` | `EDINET DB` |

## トラブルシューティング

### Codex CLI で EDINET DB に接続できない

1. 環境変数 `EDINETDB_AUTH` が設定されているか確認

```powershell
echo $env:EDINETDB_AUTH
```

2. 設定されていない場合、APIキーを登録

```powershell
.\scripts\set-edinetdb-mcp-key.ps1 -ApiKey "your-key"
```

3. **新しいターミナル** を開いて codex を起動

### 「EDINET DB のデータが自作DBと違う」

- これは正常です。EDINET DB は最新データ、自作DB は蓄積済みデータです。
- 最新に更新したい場合は、検証後にバッチ処理で自作DBに反映してください。

### 自作DB の設定が変わった

- EDINET DB MCP の設定作業では自作DBの設定は変更しません。
- もし変更されている場合は、バックアップから復元してください。
  - `config.toml` のバックアップ: `%USERPROFILE%\.codex\config.toml.bak.*`
